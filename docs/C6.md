# C6 Bank — gateway de pagamento

Implementação **pronta e plugada**, aguardando credenciais.

> ⚠️ **Leia antes de ligar em produção:** a documentação do C6 é fechada (só
> liberada após cadastro + homologação). O cliente HTTP foi escrito seguindo o
> padrão OAuth2 `client_credentials` que os bancos brasileiros usam, mas os
> **endpoints e nomes de campo não foram verificados** contra a doc oficial.
> Nada disso impede o resto: a loja continua vendendo pelo Mercado Pago.

---

## 1. Como conseguir as credenciais

1. Ter **conta PJ no C6 Bank**.
2. Cadastrar a empresa em <https://developers.c6bank.com.br/> — libera a
   documentação e o ambiente de teste.
3. Solicitar **homologação** da integração (o C6 valida antes de liberar produção).

**Perguntar ao gerente/suporte do C6:**

- A API de e-commerce tem **checkout hospedado / link de pagamento**?
  Se exigir capturar o cartão no nosso formulário, entramos em **PCI-DSS**
  (certificação cara). Com checkout hospedado ou tokenização, não há problema.
- Tem **webhook** de mudança de status? Como a requisição é assinada?
- A API exige **mTLS** (certificado cliente)?
- Taxas por transação (crédito, débito, Pix) e prazo de repasse.
- Existe **sandbox**?

---

## 2. Como ligar (quando as credenciais chegarem)

Preencher as envs (local em `.env.local`, produção na Vercel) e **redeploy**:

```
PAYMENT_GATEWAY=c6
C6_CLIENT_ID=...
C6_CLIENT_SECRET=...
C6_ENV=sandbox          # depois: production
C6_WEBHOOK_SECRET=...   # quando o C6 fornecer
```

Cadastrar a URL de webhook no portal do C6:

```
https://aromahaus.vercel.app/api/c6/webhook
```

Voltar para o Mercado Pago é trocar uma variável: `PAYMENT_GATEWAY=mercadopago`.

## 3. O que ajustar na doc oficial

Tudo que depende do contrato da API está num **único bloco**:
`C6_CONTRACT`, no topo de [`lib/payments/c6.ts`](../lib/payments/c6.ts).
O resto do arquivo é genérico e não deve precisar de mudança.

| Item | Onde | O que confirmar |
|---|---|---|
| URLs sandbox/produção | `baseUrl` | hosts reais |
| Token OAuth2 | `endpoints.token` | caminho, `grant_type`, escopo, se as credenciais vão em Basic ou no corpo |
| Criar cobrança | `endpoints.createCharge` | caminho e **nomes dos campos** do payload |
| Consultar cobrança | `endpoints.getCharge` | caminho |
| Ler a resposta | `responsePaths` | onde vêm `checkout_url`, `id` e `external_reference` |
| Status | `statusMap` | valores reais (apagar os que não existirem) |
| Assinatura do webhook | `verifyC6Signature` | header usado e o que exatamente é assinado |
| Valor | `createCharge` | se o `amount` é em **centavos** (assumido) ou reais decimais |

### Se o C6 exigir mTLS (certificado cliente)

Não deixamos isso pronto para não adicionar dependência por suposição. Se a
homologação confirmar que é necessário:

```bash
npm i undici
```

E em `lib/payments/c6.ts`, trocar `c6Fetch` por:

```ts
import { Agent } from "undici";

let agent: Agent | undefined;
function getAgent() {
  const cert = process.env.C6_CLIENT_CERT;
  const key = process.env.C6_CLIENT_KEY;
  if (!cert || !key) return undefined;
  agent ??= new Agent({
    connect: { cert: cert.replace(/\\n/g, "\n"), key: key.replace(/\\n/g, "\n") },
  });
  return agent;
}

async function c6Fetch(path: string, init: RequestInit): Promise<Response> {
  const dispatcher = getAgent();
  return fetch(`${baseUrl()}${path}`, {
    ...init,
    ...(dispatcher ? ({ dispatcher } as Record<string, unknown>) : {}),
  });
}
```

Preencher `C6_CLIENT_CERT` / `C6_CLIENT_KEY` com o PEM (`\n` escapado).

## 4. Arquitetura

O checkout não conhece gateway nenhum: ele pede `getActiveGateway()` e chama
`createCharge()`. Trocar de gateway (ou adicionar outro) não toca no checkout.

```
app/(store)/checkout/actions.ts
        │  getActiveGateway()  ← escolhe por PAYMENT_GATEWAY
        ▼
lib/payments/index.ts
        ├── mercadopago-gateway.ts ──► lib/mercadopago.ts   (inalterado)
        └── c6.ts                                            (novo)
                 │
                 ▼  ambos implementam PaymentGateway (types.ts)

app/api/mercadopago/webhook  ─┐
                              ├─► applyPaymentSnapshot()  (order-events.ts)
app/api/c6/webhook           ─┘     status + estoque + e-mails
```

`applyPaymentSnapshot()` centraliza os efeitos de pagamento — baixa de estoque
(RPC idempotente), e-mail de pago, aviso ao lojista e devolução de estoque em
cancelamento/estorno. Antes isso vivia dentro do webhook do Mercado Pago; agora
os dois gateways compartilham exatamente a mesma regra.

### Segurança mantida
- O webhook **nunca confia no corpo** recebido: consulta o status na API do gateway.
- Assinatura validada quando o segredo está configurado (mesma política do MP).
- Preços sempre recalculados no servidor.
